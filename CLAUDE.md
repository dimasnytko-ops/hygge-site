# Сайт — правила проекта

Сайт работает на телефонах и компьютерах, но **основная аудитория — мобильные пользователи**.

## Mobile-first
- Базовые стили пишутся под телефон (ширина 360–430px), десктоп добавляется через `@media (min-width: ...)`.
- Брейкпоинты: 640px (большой телефон/планшет), 1024px (ноутбук), 1280px (десктоп).
- `<meta name="viewport" content="width=device-width, initial-scale=1">` на каждой странице.
- Никакого горизонтального скролла на ширине 360px.
- Зоны нажатия не меньше 44×44px, расстояние между кнопками ≥ 8px.
- Размер шрифта основного текста ≥ 16px (иначе iOS зумит поля ввода).
- Учитывать вырезы экрана: `env(safe-area-inset-*)`, высоту экрана задавать через `dvh`, а не `vh`.
- Не полагаться на hover — всё должно работать касанием.
- Для полей ввода указывать подходящий `type`/`inputmode`/`autocomplete` (tel, email, numeric).

## Производительность (мобильный интернет)
- Картинки: WebP/AVIF, `srcset`/`sizes`, `loading="lazy"` для всего ниже первого экрана, явные `width`/`height`.
- Минимум JS и сторонних скриптов; шрифты — с `font-display: swap`.

## Проверка
- После изменений проверять вёрстку на 375×812 (мобильный) и на десктопе — через встроенный браузер или Playwright.
- Проверять доступность: контраст, `alt` у картинок, подписи у полей.

## Устройство проекта
- Студия автопортрета HYGGE, Тюмень. Сайт: https://hyggestudios.ru, репозиторий `dimasnytko-ops/hygge-site`.
- Astro (статический сайт), одна главная `src/pages/index.astro` + `404.astro`, общий каркас — `src/layouts/Base.astro`.
- Публикация: push в `main` → GitHub Actions (`.github/workflows/deploy.yml`, Node 24) → GitHub Pages. Домен в REG.RU, `public/CNAME`.
- Если сборка в Actions упала — текст ошибки в аннотации «Ошибка сборки» на странице запуска.

## Что меняет владелец сам (админка)
- https://hyggestudios.ru/admin/ — Sveltia CMS, настройки в `public/admin/config.yml`, вход по токену GitHub.
- Данные: `src/data/prices.json`, `contacts.json`, `texts.json`, `faq.json`; акции — `src/promos/*.md`. Код читает их через `src/data/site.ts`.
- Владелец коммитит прямо в `main` из админки — **перед правками всегда `git pull`**.
- Добавляя новый текст на сайт, выносить его в эти JSON и в `config.yml`, а не писать в разметку.
- Инструкция для владельца — `КАК-РЕДАКТИРОВАТЬ.md`.

## Правила по содержанию
- Факты о студии не придумывать — только от владельца. Внутренние заметки — `content/notes.md` (не в git).
- Мессенджеры равноправны: Telegram, Max, ВК, телефон — главный не выделять.
- В коммитах — noreply-адрес GitHub владельца, не реальная почта.
